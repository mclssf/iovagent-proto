# IOVAgent 产品上下文

## 1. 产品定位

`iovagent` 是「大卡数字人」的纯前端产品原型和可交互演示 Demo，用于展示和验证物流 AI Agent 的业务价值、用户流程、执行反馈和 Skill 交互，不是独立产品，也不是生产业务系统。

现有用户侧使用“物流通用智能体”等展示名称，登录页可以使用“大卡数字人”。产品归属的明确不要求修改现有页面文案、导航或布局。

主要使用场景是产品评审、客户演示、方案交流以及研发沟通。演示应让使用者理解“输入什么、Agent 如何处理、得到什么、下一步能做什么”，而不是以原型替代真实运输调度、后台调度器或生产数据平台。

## 2. 使用者与业务场景

面向调度、运输运营、客服、项目负责人、经营分析人员，以及配置数据员工和 Skill 的运营人员；不因货主、3PL 或承运商身份另建一套产品框架。

| 场景 | 需要展示的业务能力 | 典型交互与结果 |
| --- | --- | --- |
| 智能体工作台 | 理解物流自然语言需求，组织多步处理 | 对话或上传文件，展示执行过程，返回可独立理解的文字、文件或动态 H5 |
| 运单处理 | 文件导入、字段识别、项目归档、填表及纠错 | 上传 Excel，按当前演示规则解析和校验，进入新建或合并项目流程，生成结果文件 |
| 车辆与运单查询 | 区分车辆定位和运单运输情况 | 保留用户输入的车牌或运单号，展示 POI、运输节点、预计到达等信息及地图 |
| 轨迹地图 | 表达车辆位置、运输路线及历史到访 | 使用高德地图展示标记、道路路线和时间线；业务定位与轨迹可使用合理的 Mock 数据 |
| 异常监控 | 区分真实业务风险与合理停靠等情况 | 展示停车、掉线、偏移、时效等判断依据、关联运单和建议动作 |
| 普通任务 | 承接一次性、耗时或批量处理 | 多入口创建任务，展示执行进度、历史执行和结果，支持 ZIP 结果包下载 |
| 运单补全与轨迹留证 | 从已知装货端或卸货端补全另一端，整理业务核验资料 | 在普通任务上传 Excel，模拟规则推断，逐单生成带企业水印的高德地图轨迹图片及 ZIP；推断值不覆盖原始已知值，图片不作为真实审计凭证 |
| 监听任务 | 表达持续接收数据或业务事件后处理 | 例如“邮件处理订单”，通过模拟收件、处理步骤和结果演示持续工作 |
| 定时任务 | 表达按计划重复执行的业务需求 | 例如每日在途风险简报；具体入口与演示内容以所在分支为准，不代表真实服务端调度 |
| Skill 交互与运营配置 | 表达能力选择、数据源连接和配置联动 | 数据员工负责系统接入与映射，通用 Skill 负责业务能力；演示配置、可见范围及使用过程 |
| 微信群运单采集 | 将微信群作为项目运单数据源 | 在数据员工中选择多个“群消息录单员”，查看来源群、绑定微信号、在线状态和自然语言识别说明 |

以上是整体展示能力范围，不是新增功能清单，也不代表当前分支全部开放这些入口。中长期材料中的生产集成、审批、写回等设想不能直接视为已实现能力。

## 3. 真实能力与模拟能力边界

| 能力 | 原型中的边界 |
| --- | --- |
| 页面、表单、导航与交互 | 在浏览器中真实可操作，复用现有前端组件和状态管理 |
| 文件解析与下载 | 已实现的 Excel 解析及文件打包应真实执行；文件内容和统计须与演示承诺一致。未实现的语义理解明确按模拟处理 |
| 地图 | 高德地图 JS API 2.0 底图、地图控件和已接入的路线服务可真实调用；地图真实不代表车辆业务数据真实 |
| 模型推理、Skill 与工具调用 | 未接入时使用可识别的 Mock 数据和分步模拟，不以加载动画或调用文案冒充已接通模型或工具 |
| 任务执行与恢复 | 使用前端状态、计时和浏览器存储模拟。恢复页面时按已有逻辑推进，不承诺关闭浏览器后仍有服务端持续执行 |
| 登录、TMS、邮箱与通知 | 未接入时模拟授权、收件、录单、发送和回执；不真实发送邮件或短信，不擅自写入外部业务系统 |
| 已有外部集成 | 保留当前分支已存在且获明确授权的集成边界，真实调用与模拟结果分别说明；没有接入的部分不能作生产承诺 |

模拟属性与真实能力边界应在内部规则、需求文档及实现说明中清楚记录；用户可见界面按正式产品呈现，不添加“原型”“演示”“Demo”“Mock”“模拟数据”等制作属性标签。界面仍须如实保留推断、待核验、未连接、失败等业务事实。Mock 数据必须符合物流常识：编号一致、时间有先后、里程和进度合理、汇总与明细对应。

地图等已有能力所需的安全代理是配套集成，不等于本仓库需要建设生产后端。密钥和账号密码不得写入代码、日志、截图或文档；外部发送及业务写回必须单独取得用户明确授权。

## 4. 关键设计决策

### 4.1 自由对话与项目上下文分离

- 自由对话不强制绑定项目或数据员工，不自动读取企业或项目私有数据。
- 项目承载运单、数据源、技能及在途上下文；切换项目和会话时不混写消息或结果。
- 创建或编辑项目保持字段、选择规则和状态回显一致，取消不改变原上下文。

### 4.2 保持现有工作台框架

- 复用左侧导航、会话主内容和按需展示的 H5 等工作区，不因编写产品说明重构界面。
- 动态页面与对话保持同一查询对象；文字结果不依赖地图或外部页面才能理解。
- 沿用紧凑、清晰、适合重复操作的 ToB 界面，不改为营销页面。

### 4.3 展示完整且可解释的执行过程

- 复杂演示形成“用户输入、意图识别、步骤执行、结果、可选文件或 H5”的闭环。
- 每一步说明所读取的数据、所用能力和所得判断；模拟延迟用于表达过程，不作为真实执行的证据。
- 用户输入的标识在会话、地图、任务和文件中保持一致；缺少对象时按场景追问，不擅自替换为默认对象。

### 4.4 当前任务范围与长期能力分开记录

截至 2026-10-19，`v256` 的“做任务”新增入口只创建一次性普通任务，已有“邮件处理订单”固定监听卡片继续保留，项目运单状态判断独立运行。此处记录当前基线，不要求其他分支回退到这一状态。

- 普通任务可以从公共入口、项目入口或工作台 Agent 决策进入；保留个人或项目归属。
- 工作台先调用 Excel 解析 Skill，再判断是否存在超过 180 天的运单或超过 100 条的运单。历史记录选择历史业务质量分析接口的模拟方案，大批量不自动等同于历史查询。
- 任务与每次执行记录分离；重新执行不覆盖旧结果，停止保留有效部分。结果和下载页面提供 ZIP 结果包，不恢复逐条明细入口、任务摘要、结果继续提问、待确认通知或未读气泡。
- 监听和定时属于整体可展示的业务模式，但不能因本文列出这些能力，恢复 `v256` 已移除的通用条件触发、定时或监听任务创建入口。后续调整需有明确需求。

### 4.5 数据员工与通用 Skill 分工

- 数据员工表达 TMS 等系统连接、登录、数据获取和字段映射。
- 通用 Skill 表达在途专家、运营助手、经营分析参谋、运力与货源等业务能力，不接管数据员工的接入配置。
- 运营侧的可见范围、启停、名称和描述按当前实现与用户侧联动，不在页面和 Store 各维护一套相互矛盾的数据。

### 4.6 保持技术栈与架构

沿用 Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus、Tailwind CSS 4、SCSS 及高德地图 JS API 2.0，使用 pnpm 管理依赖。文件能力沿用现有 SheetJS、fflate 等依赖。

未经明确要求，不新增生产数据库、队列、任务调度服务、Agent 后端或独立认证系统，不迁移框架或重新划分应用架构；优先复用既有 Store、组件、工具函数与浏览器 API。保留已有安全代理和明确授权的工具集成，不擅自扩展其职责。

### 4.7 群消息录单员归属数据员工

`v259` 将微信群运单来源纳入数据员工，用户侧统一命名为“群消息录单员”。一个实例对应一个企业、一个微信号和该账号加入的一个群；同一微信号的不同群分别形成实例，项目可以多选本企业的多个实例，与现有系统和表格来源并存。

卡片以群名区分实例，详情展示数据获取方式、自然语言识别说明、绑定账号、来源群及在线状态。微信账号离线保留绑定及项目选择，并显示当前无法获取新消息。创建与编辑项目共用同一目录，卡片详情与 agent-ops 数据员工配置共用来源信息。

未来由内部协作团队提供微信消息收集和运单识别提取能力，agent-ops 的独立微信通道管理负责企业、账号、群及录单员的绑定和状态。当前只实现前端卡片、详情和项目选择；账号、群和状态来自本地样例目录，企业范围固定为现有华东客户，未接入真实微信。独立通道管理页与实际录单链路不属于本轮范围，界面沿用正式产品用语。

### 4.8 正式产品化的界面呈现

自 2026-10-21 起，所有前端功能的用户可见文案按正式产品标准设计，范围包括用户侧、登录页、运营后台、Agent 消息及执行过程、H5、生成文件和图片水印；不显示“原型”“演示”等制作属性说明。具体执行及验收规则统一见根目录 `AGENTS.md` 的“用户可见界面规范”。

该决策只改变展示口径，不改变本仓库的纯前端定位、Mock 实现或外部调用授权边界；不得据此接入生产后端、伪造真实数据来源或隐去必要的业务核验信息。内部文档保留真实能力说明，用户原文、代码标识和技术路径不作机械替换。

### 4.9 运单详情地图水印与截图

运单详情页提供水印开关，不提供独立截图按钮；批量留证流程继续生成轨迹截图。标题使用“监控运输轨迹”，企业、车牌、运单号、装卸货 POI、经纬度及运输时间全部叠加在地图内；不在截图上显示推断来源、制作属性或“非实测”等说明。未完成卸货的运单显示“待卸货”，不将预计到达时间作为实际卸货时间。

2026-10-23 调整详情页为左侧大地图、右侧上方运单信息和下方紧凑事件流。详情页事件流只呈现现有判断结论，不再提供规则判断切换；其他页面的判断模式不受影响。水印开关位于地图右上角浮层，水印信息使用透明背景文字，按左上角身份信息与底部装卸货信息布局，预留边距和地图控件空间，不再铺设白色底板。

水印左上角使用用户提供的透明背景兴路车联 Logo 原图，独立占一行，下方另起一行显示“监控运输轨迹”；页面与批量留证共用同一品牌素材，不以混合模式代替图片透明通道。高德地图底图统一使用 `amap://styles/macaron`，不改变路线、标记及地图联动。

详情栏适度加宽，标题与正文采用工作区现有的紧凑字号，沿用白色主体和浅蓝摘要，运输状态与风险等级分开展示；普通事件紧凑排列，异常事件用轻量风险卡片突出。事件筛选、排序及原始结论不变，补充说明可展开。列表点击与地图标记复用同一信息窗并同步选中高亮；仅事件列表承担面板主要滚动，不新增业务处置流程。

详情页与批量留证共用地图水印 DOM 和截图方法，直接截取地图容器，不再另行拼接地图外的页眉、明细或页脚。原始已知字段和规则补全来源仍保存在 ZIP 内的明细中，真实地图与本地 Mock 业务数据的实现边界不变，不意味着已经接入历史 GPS 轨迹或生成真实审计凭证。

### 4.10 连续分栏工作区

智能体工作台、做任务和运单详情采用统一的连续分栏工作区：导航、主内容及详情或结果栏衔接成整体，内容铺满可用区域，不放入独立圆角外框或带留白的整页卡片。分栏沿用中性底色与细接线，内部信息仍保留必要间距。运单详情的地图与详情栏按该规范与导航直接衔接。

该规范属于页面布局类型，不意味着所有页面都必须有三个可见栏目，也不改变既有右栏显隐、功能或业务流程；窄屏允许折叠或上下排列。完整执行规则见根目录 `AGENTS.md` 的“连续分栏工作区页面规范”。

运单列表与异常运单列表同样采用一体化工作区：标题、统计或分析、筛选与表格连续衔接，不再包裹整页圆角框，表格承担主要滚动。项目导航不显示“运单详情与地图”，但两个列表的“查看详情”仍进入原详情页。异常列表移除“生成简报”“下载当前结果”及对应生成逻辑；普通运单列表的下载入口保留，既有分析、筛选与地图联动不变。

- 当前明确需求和当前分支代码优先于历史说明；若发现冲突，先说明差异，不依据旧材料恢复已删除功能。
- `outputs/` 用于具体版本的需求和评审交付物；`docs/` 中其他中长期场景材料用于理解方向，不作为当前功能完成清单。
- 产品定位、模拟边界、技术栈或关键交互决策发生变化时，同步更新相关段落。保留未变化的内容，标明版本适用范围，不把局部改动扩大为整套产品重构。
- 文档不保存真实密钥、账号密码、验证码或客户敏感数据。
