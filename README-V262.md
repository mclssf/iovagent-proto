# V262：基于 V260 的需求增量（本地 V2.4）

本次将本地 V2.4 源码同步到 `V262-in-transit-monitoring`，保持代码位于仓库根目录。沿用 V260 的在途监听流程，并增加以下三项需求。

## 1. 轨迹规划与展示

- 新运单按项目配置记录规划策略和本单路线版本，已有运单不因项目策略变更而自动重规划。
- 地图分开展示规划轨迹、实际轨迹及事件标记；实际轨迹只使用已提供的定位点，不把规划路线当作实际行驶记录。
- 没有实际轨迹时显示“暂无实际轨迹”；车辆未入网时不展示虚构当前位置或实际轨迹。
- 高德底图、道路规划和坐标转换沿用同源安全代理。项目路线规划适配器目前使用本地回执样例，正式接入需替换为真实基础路线服务。

## 2. 未入网运单标记

- 对车辆入网查询明确返回“未入网”的运单，统一展示“车辆未入网”和“免计费”标记。
- 运单列表、异常列表、详情及项目对话查询保持一致，异常列表按运单去重。
- 停止相关监听，不将未入网状态计为停车、离线等基础运输事件；后续源数据更新不自动恢复本单监听。

## 3. 灵动接口获取运单

- 提供单向获取与导入适配流程，新运单归属配置的默认项目。
- 按客户标识和源运单号去重，比较源更新时间，保留源字段快照、同步摘要与失败原因。
- 切换默认项目只影响后续新运单，不迁移已有运单；源单更新保留本地状态、实际节点、路线版本和原项目归属。
- 只读取和导入，不向灵动创建、修改或回写运单。当前 `readLingdongSample` 为本地接口样例，尚未接通真实灵动服务。

## 运行与配置

- Node.js 20 或以上，执行 `pnpm install --frozen-lockfile`。
- 启动：`pnpm dev`，默认 http://127.0.0.1:5810/index/orders 。
- 构建：`pnpm build`。
- 高德配置使用本地 `.env.local`：`VITE_AMAP_KEY` 和服务端 `AMAP_SECURITY_CODE`。个人密钥、依赖目录及构建产物不随本次提交上传。
- 补充回归：`node scripts/test-v260-supplement.mjs`；在途监听回归：`node scripts/test-in-transit-monitoring.mjs`。
