# V260 在途监控演示（V1.1）

本分支将当前 V1.1 原型放在仓库根目录，沿用既有项目结构。版本说明依据《物流数字人 V260 产品需求文档》v3.2（2026-10-22），适用于一车、一装一卸业务。

## 运行与验证

- 安装依赖：`pnpm install --frozen-lockfile`（Node.js 20 或以上）。
- 启动：`pnpm dev`，访问 http://127.0.0.1:5806/index/orders 。
- 系统任务：`/index/daily-tasks?projectId=P001`；异常运单：`/index/risk`。
- 项目详情：`/index/projects/detail?projectId=P001&tab=skills`；运单详情从列表进入。
- 构建：`pnpm build`；类型检查：`pnpm typecheck`；业务回归：`pnpm test:phase1`。
- 配置环境变量后加载高德地图；缺少地图Key时展示降级提示，不虚构实际轨迹。真实凭据由本地或部署环境提供。

## 版本描述

1. 六项系统技能随项目提供并默认开启：运单状态自动更新、超时停车、在途离线、线路偏离、晚发晚到及恶劣天气监听。技能卡片只展示信息，参数集中到“做任务—系统任务”编辑；普通任务沿用原有流程。
2. 系统任务提供搜索、状态筛选、编辑及开启／停止。参数始终展开，手动保存前校验整数、范围和步长；取消不保存，编辑弹窗不提供自然语言规则调整。POI研判和起终点经过检查默认开启，重复提醒默认30分钟、晚发晚到宽限默认60分钟。
3. 运单接入由固定代码读取项目配置，按计划时间一次性推定待发车、在途或已完成。推定不生成实际节点或围栏事实；初始化已完成的运单不注册监控。
4. 围栏事实、显示状态与人工节点时间分别保存。停车、离线支持周边POI及位置／轨迹证据的模拟研判：合理事件低风险，证据不足保留高风险；偏离、晚发晚到、未经过起终点及天气按规则处理。
5. 北京时间整点汇总上一小时结果，可按运单筛选。状态任务展示监控运单、事件及状态更新；其他任务展示监控运单、事件、高低风险及明细，恢复事件不重复计风险。
6. 运单详情左侧地图、右侧运输节点和异常，提供智能体判断／规则判断两个视图。节点支持手动更新时间和先后顺序校验；人工时间不补造围栏记录。基础事件在后台保留，用户通过任务结果及详情查看，不新增独立基础事件列表或详情菜单。
7. 建单后监听满72小时仅停止订阅和提醒；未完成运单到计划结束时间＋72小时自动完成，并执行开启的起终点经过检查。两个时限独立，退订后仍保留自动结束检查；更新配置或重新开启不延长原订阅截止。

## 演示边界

- 订阅、天气消息、POI及模型研判为本地模拟，未声明已接通生产服务。自定义过滤文字可保存，模拟结果保留待核实，不执行任意自然语言规则。
- 仅有计划推定在途、没有实际发车时间时，当前原型不生成停车、离线及偏离异常。
- 小时监控覆盖通过任务运行记录推导；正式服务需按真实订阅生效和停止区间核算。
- 不新增真实短信、邮件、群消息或车机发送，不支持多装多卸、历史轨迹初始化或超过72小时的自动续订。
- 本地演示数据沿用V1.1独立持久化。`V1-BASELINE.json`用于记录初始复制来源，不代表当前代码未变化。
