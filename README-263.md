# 263：在 260 版本基础上增加需求

本分支发布本地 V2.4 的当前源码，包含以下三项需求。当前源码与此前发布的 V262-in-transit-monitoring 一致；此次新增 263 分支及本说明，并将公开环境文件中的本地存储参数改为演示占位值，未另改业务逻辑。

## 1. 轨迹规划与展示

- 线路偏离任务增加线路策略：更多人选择（默认）、时间优先、距离最短。先规划路线，再注册偏离监听。
- 新运单保存创建时采用的策略及路线版本。修改项目策略只影响之后的新运单，已有运单不自动重规划。
- 运单详情地图区分规划轨迹与实际轨迹：规划为蓝色虚线，实际为绿色实线，可分别显示或隐藏。
- 实际轨迹只展示已提供的定位记录，按时间排序并停在最近定位点；没有定位记录时显示“暂无实际轨迹”，不延伸到目的地。
- 沿用高德在线底图、道路规划及同源安全代理。路线版本回执使用本地适配器样例，正式业务路线服务尚未接入。

## 2. 未入网运单标记

- 车辆接口明确返回未入网时，增加独立的“车辆未入网”风险标签，与高风险、低风险、待核实等已有结论并存。
- 运单列表、异常运单列表、详情及项目查询展示一致，异常运单可按未入网筛选，数量按运单去重。
- 未入网运单标记免计费，停止相关监听；不把未入网记录计入停车、离线等基础事件数，不因缺少定位误报离线。
- 本期不做入网后恢复监听，不自动取消免计费。已有异常与运输状态保留。
- 增加固定样例 V260-NET001；双轨迹样例为 V260-TRACK001，均归属华东干线在途监控项目。

## 3. 灵动接口获取运单

- 从灵动单向获取客户运单，默认同步到数字人，新增运单归属客户的默认项目。
- 项目管理增加“设为默认项目”。同一客户只有一个默认项目，切换只影响此后首次接入的新运单。
- 按客户标识与源运单号去重，比较源更新时间，保留源字段快照、同步摘要及失败原因。
- 源单更新保留原项目归属、本地运输状态、实际节点及路线，不迁移已有运单。
- 不向灵动创建、修改或回写数据。当前 readLingdongSample 为本地只读接口样例，尚未接通真实灵动接口。

## 运行与验证

使用 Node.js 20 或以上及 pnpm。安装依赖后运行 pnpm dev，默认地址 http://127.0.0.1:5810/index/orders 。构建命令为 pnpm build。

地图配置由启动电脑的 .env.local 提供：VITE_AMAP_KEY 为浏览器 Key，AMAP_SECURITY_CODE 为服务端安全密钥。安全密钥仅用于 /_AMapService 同源代理，不进入前端。地图需要联网及有效授权，仓库不包含本机真实密钥。

回归命令：

```sh
node scripts/test-v260-supplement.mjs
node scripts/test-in-transit-monitoring.mjs
pnpm build
```

本项目为前端交互原型。灵动接口、车辆入网查询、业务路线回执及计费排除使用本地状态和样例，不表示已接通生产系统。本分支保留当前 V2.4 的其他页面及交互。
